# Shubham Chaudhary - Portfolio Site

## What this is
The personal portfolio of Shubham Chaudhary (Full Stack Engineer), built as an interactive desktop:
an Apple-inspired desktop on computers and an app-style Home Screen on phones. Next.js App Router,
TypeScript strict, plain CSS (no framework). Live at https://shubhamworks.vercel.app (Vercel deploys `main`).

**Earlier Windows 95 version:** preserved on branch `windows-95-classic` and tag `win95-final`
(commit 51a3789). It was removed from `main` in Oct 2026 at the user's request - don't bring
Windows-era names, copy or assets back into `main`.

Static assets in `public/`: `Shubham_resume.pdf`, `icon.svg` (app icon source), `favicon.ico`,
`favicon.png`, `apple-touch-icon.png`, `og-image.jpg`, `sw.js` (clean-up worker, see Architecture),
`googlec9536a809aa9ed01.html` (Google Search Console ownership file;
keep it, or Search Console loses verification). `robots.txt` and `sitemap.xml`
are generated by `app/robots.ts` and `app/sitemap.ts`.

## Design
- Apple-inspired, not Apple assets: no Apple logo (the menu-bar logo is our winking-monitor
  `BrandMark`), own app tiles (`AppIcon`: CSS gradient rounded square + white SVG glyph), own
  gradient wallpapers, no Apple fonts (no bundled SF). "Inspired by", never copied.
- **Emoji are our own drawings** (Nov 2026, user's request: "custom, not anyone else's" - so no
  Twemoji / Noto / OpenMoji either): `Emoji` in `components/icons/Emoji.tsx`, 19 SVGs on a 32x32
  grid in the app tiles' style, same on every system (device emoji differed). Like toast: wink,
  love, grin, stars, glowheart, sparkheart, sparkles, popper, hands, star, party; unlike:
  letdown, teary, pensive, plead, monitor (the app icon's monitor with a tear), broken; plus
  coffee (Debug Runner) and check (contact toasts). Wink and monitor borrow the winking monitor.
  Small loops (`.emo-*` in `styles/desktop.css`, none under reduced motion); each animated part
  has no `transform` attribute so CSS can move it. Each instance makes its own gradient ids
  (`useId`): one like-button copy is always hidden, and gradients in hidden copies don't paint.
  `data-emoji="<name>"` on the svg (tests read it). The review page with all of them was a
  claude.ai artifact ("Shubham Emoji Set"). Don't add device emoji to the UI; draw a new one.
- Fonts (user's pick, Nov 2026): text uses **Figtree** (`--font-text`, read through `--font`, with
  the system stack as fallback) so Mac, Windows and Android look the same; the device's own font
  (Oct 2026 choice) differed on every system (SF / Segoe UI / Roboto). Inter was offered and
  rejected; Albert Sans was the runner-up. **JetBrains Mono** (`--font-mono`, used through
  `--mono`) is for the Terminal, dates, tech lines, skill tags and the visitor counter. Both are
  SIL OFL, loaded with `next/font/google` in `app/layout.tsx`: downloaded at build and served from
  this site. The sticky note keeps its handwriting stack (device fonts). Portfolio type scale: section titles 24px,
  body 15px / 1.6, tables and skills 14px, project/job titles 17px, stat numbers 28px. No italics
  (the user decided against them).
- Desktop vs phone is one media query: `(max-width: 700px), (max-height: 500px) and (pointer: coarse)`
  (`PHONE_QUERY` in `lib/motion.ts`, same query in `styles/ios.css`, which is imported last).
- Colors are CSS variables in `styles/base.css` with a light and a dark set (the dark set is
  duplicated under `prefers-color-scheme` for Auto). Accent `#0066cc` light, `#4da3ff` text +
  `#0068d6` fills dark, chosen for WCAG AA (Apple's `#007aff` fails for small text). Dark mode
  layers lighter as surfaces rise (page < card < rows); links/secondary buttons in the content are
  tinted accent so they read as clickable.
- One scrolling portfolio window, not a desktop simulator with a window per section (deliberate).
- Motion: Apple curve `cubic-bezier(0.32, 0.72, 0, 1)` + a gentle spring; everything is skipped
  under `prefers-reduced-motion`.

## Architecture
- `app/page.tsx` renders the portfolio sections (`components/portfolio/*`) as **Server Components**
  and passes them as props into the client desktop root `components/os/ShubhamOS.tsx`. All content
  is in the server HTML (SEO); the client only chooses which sections a tab shows and their order.
- Content lives in `data/*.ts` (profile, about, skills, projects, experience, education). Entries with
  `hidden: true` (BrowseAnywhere project, ShepHertz job) are kept but not rendered.
- `components/os/OsProvider.tsx`: one reducer for dialogs, menus, tab, toast and window status, plus
  stable actions (`useOsActions()`): `showToast`, `showMessage`, `openDialog`, `goToSection`,
  `openTerminal`, `openGame`, `openResumeWizard`, `toggleMenu`, `getDockIcon`, ... Components plug
  imperative handles/DOM nodes in via `connect.*` callback refs (`mainWindow`, `terminalWindow`,
  `mainDockIcon`, `terminalDockIcon`, `terminalConsole`, ...) because the React Compiler lint forbids
  passing ref objects around in render. Dialog ids: `message`, `closeConfirm`, `trash`, `game`,
  `settings`, `wizard`, `timeMachine`, `about`, `activity`, `links`. Window keys: `main`, `terminal`.
- `components/windows/Window.tsx` is the single generic window (drag, 8-edge resize, snap, zoom,
  minimize, phone Home button); reuse it for any new window. Discrete state is React state; live
  geometry and animations write styles via refs. It sets only `display: none` inline when hidden, so
  CSS picks grid (desktop) or flex (phones).
- `components/dialogs/Dialog.tsx` is the generic dialog: `kind: 'alert' | 'panel'`, focus in, Escape
  closes, focus returns. Panels are bottom sheets on phones (grabber, "Done"); like iOS they can
  also be pulled down to close (`enableSheetDrag` in `lib/motion.ts`:
  only from the title bar with the grabber (Nov 2026, user's call: pulling anywhere in the content
  closed sheets by accident); past a third of the
  height or a quick flick closes, otherwise it springs back; pulled up, it stretches taller with
  resistance instead of sliding, so its bottom never leaves the screen's edge (sliding showed a gap
  with the page behind - user's report, Nov 2026)). The height is pinned while dragging: Time
  Machine and Activity Monitor are taller than the 92dvh cap, and lifting the cap let them grow
  to full content height and jump past the top (user's report, Nov 2026; `mobile.spec.ts` drags
  Settings, Time Machine and Activity Monitor). Those two also scroll inside the sheet, so phone
  sheets have `overscroll-behavior-y: none` (iOS's bounce showed an empty gap above the pulled
  content), and `.time-machine` has `isolation: isolate` so its year and edge note stay under
  the sticky title bar. Contents stay mounted
  while closed.
- CSS in `styles/*.css`, imported in order by `app/globals.css`. No Tailwind, no CSS-in-JS.
- localStorage-backed preferences use `lib/stored-value.ts` (`useSyncExternalStore`, server snapshot =
  default) so there are no hydration mismatches. Keys are in `lib/storage.ts`; their string values
  (`shubhamOsTheme`, ...) are kept as-is so visitors' saved settings carry over.
- Theme: Light / Dark / Auto via `data-theme` on `<html>`. **Default is Light** (the server HTML
  ships `data-theme="light"`); an inline pre-paint `<script>` in `app/layout.tsx` applies a saved
  choice (`next/script` `beforeInteractive` runs too late in the App Router). `<html>` has
  `suppressHydrationWarning`.
- Site URL for canonical/OG/sitemap: `lib/site.ts` -> `NEXT_PUBLIC_SITE_URL` ->
  `VERCEL_PROJECT_PRODUCTION_URL` -> `https://shubhamworks.vercel.app`.
- **Not a PWA** (removed Nov 2026 at the user's request): no web app manifest, no offline cache.
  Browsers that installed the old offline-cache service worker (cache `shubham-os-v6`) still get
  it removed: `public/sw.js` is now a clean-up worker (deletes all caches, unregisters itself; no
  fetch handler; `next.config.ts` serves it with `no-cache`), and `ServiceWorkerCleanup`
  (`components/shared/`, in `app/layout.tsx`) unregisters any registration and clears caches on
  page load. Both can be deleted after a few months. Tests: `tests/e2e/no-pwa.spec.ts`.
- Vercel Web Analytics and Speed Insights (Core Web Vitals from real visits; added Nov 2026 at the
  user's request): `<Analytics />` and `<SpeedInsights />` in `components/shared/VercelInsights.tsx`,
  rendered from `app/layout.tsx` only when `process.env.VERCEL` is set (their scripts 404 off
  Vercel). Each is enabled once in the Vercel dashboard (Analytics tab, Speed Insights tab).
  - Owner opt-out (`lib/owner-device.ts`): a secret token after `#` marks a browser as the owner's
    (saved under `shubhamOsDevice`), token + `.on` undoes it; nothing loads until checked. Only the
    token's SHA-256 is in the repo - never commit the token. Not in the README on purpose (user's
    call; the repo is public). Tests: `tests/e2e/owner-device.spec.ts`.
- **Likes** (Nov 2026, the site's first server data, user's request): `app/api/likes/route.ts`
  (`GET` -> `{ count }`, `POST` adds one -> `{ count, id }` (`id: null` over the daily limit),
  `DELETE` `{ id }` takes one back -> `{ count, removed }` (400 for a malformed id); a different
  `Origin` gets 403; 503 when unconfigured or Upstash fails) over `lib/likes-store.ts`, which calls Upstash Redis's REST `/pipeline` with
  `fetch` (no `@upstash/redis` dependency). Database `shubham-portfolio-kv` (Upstash via the Vercel
  Marketplace, Mumbai, free plan, eviction off), env `KV_REST_API_URL` / `KV_REST_API_TOKEN`
  (also in `.env.local`). Keys: `likes:count`; `likes:ids` (set of the server-made UUIDs of likes
  that can be taken back: a DELETE lowers the count only if `SREM` removed its id, so made-up or
  repeated requests can't remove other people's likes; likes from before ids existed stay
  counted); `likes:ip:<HMAC of IP>` counts likes per network
  per day (max 5, expires after 24h; shared office / mobile-carrier IPs are why it isn't 1;
  unlikes don't give the quota back).
  Playwright sets both env vars to a dead address so tests can't touch the real count.
  The Upstash `fetch` helper (`pipeline`, `signHex` HMAC keyed by the token) is `lib/kv.ts`;
  shared route bits (`NO_STORE`, `fromOtherSite`, `clientIp`) are `lib/api-response.ts`.
- **Debug Runner top score** (Nov 2026, user's request): the highest score of all players.
  `POST /api/debug-runner/run` -> `{ ticket }` (`<start ms>.<nonce>.<HMAC>`, stateless);
  `POST /api/debug-runner` `{ ticket, score }` -> `{ best, record }` (400 for a bad/old/reused
  ticket or a score above `maxScoreFor`: `POINTS_PER_SECOND` (10, exported from
  `lib/debug-runner.ts`) x seconds since the ticket x 1.05 + 30); `GET` -> `{ best }`; 403 from
  other origins, 503 when unconfigured. Server `lib/runner-score-store.ts`, browser
  `lib/runner-score-client.ts` (`useTopScore`, `loadTopScore` on first open, `startRun` /
  `finishRun`). Keys: `debugRunner:top` (sorted set, member `best`, `ZADD GT CH` so it only
  rises; CH tells whether it was a record), `debugRunner:run:<nonce>` (`SET NX`, 1h expiry, one
  submit per ticket). No player names (nothing to moderate).
- Keyboard: Escape closes menus/dialogs; Enter/Space activates menu items, tabs and window buttons;
  Enter opens a focused desktop icon.
- `AGENTS.md` is auto-generated by `next dev`; leave it uncommitted.

## Desktop (computers)
- `MenuBar`: logo button `#logo-menu-button` opens `AppMenu` (`#logo-menu`, with a Links
  submenu), section links, clock. The logo menu has no section shortcuts (About Me ... Contact;
  removed Nov 2026 at the user's request): computers have them in the menu bar and the sidebar,
  phones in the app's tab bar. Desktop menus (logo menu,
  submenu, right-click menu) use `--menu-material`: in Light a see-through glass (0.72; the
  opaquer `--material-strong` looked solid over the white window), in Dark the original
  `--material-strong` (more see-through looked bad there - user's call).
- `Dock`: `#dock-portfolio`, `#dock-terminal`, `#dock-game`, `#dock-timemachine`, `#dock-activity`, `#dock-settings`, `#dock-resume`,
  `#dock-trash` (`#dock-more` is phone-only). Magnification is JS (`useMagnification`): cosine
  falloff by pointer distance against the resting layout, written to `--s` per item; items widen (so
  the dock grows) and icons scale from their bottom edge. Launch bounce animates the tile, not the
  button. Running dots.
- Portfolio window (`#window`) is laid out like a Mac app (CSS grid in `styles/window.css`): unified
  52px title bar, translucent sidebar (`.window::before`, backdrop blur) with the profile card (the
  server `InfoBar` with avatar initials; its "Name:/Role:/Status:" labels are visually hidden but kept
  for screen readers) and the section list (the tablist, colored `tab-tile`s, a selection highlight
  that glides between rows). Content and status bar on the right.
- Status bar (`StatusBar.tsx`, Time / Status / Made with / © / like + visitor chips) is always one
  row on computers (it used to wrap to two rows - user's report, Nov 2026): a container query on
  `.status-bar` (em widths, so Larger Text works too) hides Made with, then ©, Status, Time as the
  window narrows; the chips always stay; "Made with" can also shorten with an ellipsis. Phones
  keep the wrapped, centered footer. Test: `desktop.spec.ts`.
- Tabs (`lib/sections.ts`, Oct 2026): Home (every section), About (About + Experience), Projects,
  Skills, Contact. Skills got its own tab at the user's request (it used to sit under Projects).
  The phone tab bar holds all five.
- Profile photo: `public/profile.jpg` (192px square crop of the user's photo; the original is kept
  in `assets/profile-photo.jpeg`, not served). Shown in the sidebar profile card (`InfoBar`, path in
  `PROFILE.photo`) and used as the JSON-LD `Person` image. Hidden in the phone info row.
- Window buttons (`.tl` in `styles/window.css`) follow macOS: 12px, 8px apart, each with a darker
  edge and a tinted symbol in its own color (shown while pointing at the group). The symbols are
  our own SVGs (`WindowGlyph` in `components/icons`), drawn on the button's 12x12 grid so they
  are centered and sharp; not Apple's artwork. They turn gray
  (`--tl-off`) while the browser window isn't focused (`data-inactive` on `<html>`, set in
  `useDesktopEvents`). Panels show the close button plus a gray, disabled minimize and zoom
  (exception: the green button works in the Time Machine and Activity Monitor, see below; its minimize stays gray on purpose -
  the genie can't copy the starfield canvas).
- Desktop icons (Shubham HD, Debug Runner, Time Machine, Activity Monitor, Terminal, Trash) in a top-right column; double-click with
  a mouse, single tap on touch. The default Aurora wallpaper drifts slowly (`LiveWallpaper`).
- Animations (`lib/motion.ts`, all return a cancel function):
  - Minimize = real genie: the window is copied into 10-16 horizontal strips (each only its slice's
    size; copies have no blur/shadow; off-screen sections become spacers) and each frame every strip
    gets a `matrix3d` "square to quad" transform onto its slice of a funnel into the dock icon.
    Transform-only, so nothing repaints per frame. It lagged badly when copies kept the sidebar blur
    and used clip-path - keep it transform-only.
    Exception: a window that is frosted glass itself (the Terminal) gets one funnel-shaped
    `.genie-glass` backing (its own blur + background, clip-path updated per frame) and its copies
    are drawn without a background. See-through strips showed dark lines where the 1px overlaps
    doubled up, light seams without the overlap, and lost the blur. The Terminal's invisible input
    is dropped from the copies (it's styled by id, which copies lose, and showed as a white box).
    The drop shadow stays on during the genie: the funnel is drawn with a canvas shadow (same blur
    radius as the window's computed `box-shadow`) into a quarter-size `<canvas class="genie-shadow">`
    that CSS stretches to full size. A CSS `filter: blur()` on a full-size element cost ~2x the
    slow frames on the user's integrated GPU (AMD Vega 3); scaling a filtered element with CSS
    doesn't reliably blur at the small size, the canvas does.
    Setup cost is mostly laying out the 10-16 copies. Each strip's copy swaps the blocks of the
    on-screen section that lie outside its slice for same-size empty boxes (`trimToSlice`; only
    blocks whose children's margins can't leak out: text-only blocks, tables, grids, flex). This
    was checked pixel-for-pixel against untrimmed copies on every tab. CSS `contain` on the strips
    made no measurable difference.
    Copies are prepared ahead of the click: when a mouse rests ~80ms on the window buttons or on
    the window's dock icon, `prepareGenie` (called from `Window.tsx`) builds the copies into an
    invisible layer (`.genie-layer--prepared`, opacity 0) so they are laid out before the
    click (Chrome doesn't draw invisible layers, so they are still drawn on the first frame;
    parking them just off-screen instead was tried in Nov 2026 and didn't avoid that either);
    a minimized window is displayed invisibly for a moment to be copied. On click,
    `genie` uses them only if still valid (same rect and scroll, no content mutations other than
    text, under 5s old; for a minimized window: no content mutations and the same browser size),
    otherwise it builds anew as before. On the user's machine this cut the
    click-to-motion pause from ~58ms to ~9ms. The portfolio window's pause comes from its size
    and content (~10x the Terminal's elements), not from the shadow.
    Keeping the click light (Nov 2026, the user saw a hitch on the portfolio window but not the
    Terminal): `Window.tsx` tells the rest of the desktop (`onStatusChange`: Dock, menu bar,
    dialogs) about minimize/restore when the genie **lands**, not on the click (re-rendering them
    cost ~12ms before the first frame). Restore from valid prepared copies (`canRestoreFromPrepared`)
    keeps the real window `display: none` until the genie lands (laying it out on the click cost
    ~40ms); Chrome keeps its scroll position. The live wallpaper is paused with
    `.os-animating .live-glow`, a class, not `span`: a rule ending in a tag name made Chrome
    restyle every span on the page, including all the copies (~870 elements), on each animation.
    Before copying, the genie fires `BEFORE_GENIE_COPY` on the window so JS-measured layout can
    re-measure (the sidebar's selection highlight is 0px wide while the window sits in the Dock).
  - **Maximize = full screen, Dock on top** (Nov 2026, user's call: every app the same). The
    green button on the portfolio window, the Terminal, the Time Machine and Activity Monitor
    covers the whole screen, menu bar included; the Dock floats above it. Layers: maximized
    windows 91 (Terminal 92 while the portfolio is maximized, so it stays reachable), zoomed
    panels 93 (`.dialog-overlay--zoomed`), Dock 98, other dialogs 200. Each pads its bottom by
    `--dock-reserve` (status bar, `.terminal-body`, `.activity`, `.time-machine`) so nothing
    sits behind the Dock. Half-screen snaps still stop at the menu bar and Dock.
  - Zoom = `animateFrame`: glides the real frame (inline !important left/top/width/height) while the
    tab panel is frozen at its final width, so text lays out once, not per frame. While it glides
    the window has `.window--gliding`, which gives the tab panel, sidebar list and profile card
    their own GPU layers (`will-change: transform`): otherwise Chrome redrew all their text every
    frame (~300ms of drawing per zoom on the user's machine, now ~90ms; the sidebar blur and the
    shadow were measured and aren't the cost). Swapping the text for placeholder bars during the
    glide was discussed and rejected: the swap would show at the slow start and end.
  - `animatePopIn` uses WAAPI and never touches inline transform (the main window keeps inline
    `transform: none` once centered; `resetWindowStyles` preserves it).
  - Clicking the dock icon mid-minimize reverses it. `.os-animating` on `<html>` pauses the live
    wallpaper during window animations.

## Features
- **Startup screen** (revamped Oct 2026): dark screen with a soft Aurora glow, the app icon springs
  in, then the user's name and role, a thin progress bar with plain steps ("Loading projects"...;
  "Welcome back" for returning visitors), then it zooms gently out into the desktop. Deterministic
  ~4.4s. Click or any key skips it ("Tap to skip" on touch screens). Timing is intentionally fixed;
  total must stay within 4-6 seconds if changed.
- **Terminal** (`components/windows/TerminalWindow.tsx`, commands in `lib/terminal.ts`): prompt
  `shubham@portfolio ~ %`, `help`, `whoami`, `skills`, `projects`, `resume`, `links` (plus one
  command per profile link id), `sudo hire-me`, history
  with Up/Down, zsh-style "command not found". Hidden commands (`sudo hire-me`, `matrix`,
  `rm -rf ...`) aren't in `help`, but `help` ends with "Psst: 3 commands are hidden. Type 'hint'
  for a clue." and each `hint` gives the next clue (`HINTS` in `lib/terminal.ts`; clues, never
  the command itself - user's point, Nov 2026: unmentioned easter eggs nobody finds). Keep the
  count in sync when adding one. `echo` alone prints an empty line. Output persists across minimize/close; only `clear`
  empties it. The prompt line follows the output (one scrolling `.terminal-body`) and draws a block
  cursor (blinks when focused, hollow when not, follows arrow keys); the real `#terminal-input` is
  invisible and laid over the typed text, so typing, history and phone keyboards still work.
- **Debug Runner** (`components/dialogs/DebugRunnerDialog.tsx`, engine + drawing in
  `lib/debug-runner.ts`, a canvas; Nov 2026 upgrade at the user's request): movement is per second,
  not per frame (the first version ran twice as fast on 120Hz screens). Tap = small hop, hold
  (Space, mouse or finger) = higher jump (low gravity while held, up to 0.25s; letting go early cuts
  the climb; a press just before landing still jumps). Obstacles join as the score grows: bug (any
  jump), **memory leak** (a wide puddle, only a held jump clears it; width follows the speed),
