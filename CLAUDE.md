# Shubham Chaudhary - Portfolio Site

## What this is
The personal portfolio of Shubham Chaudhary (Full Stack Engineer), built as an interactive desktop:
an Apple-inspired desktop on computers and an app-style Home Screen on phones. Next.js App Router,
TypeScript strict, hand-written CSS. Live at https://shubhamworks.vercel.app (Vercel deploys `main`).

**Earlier Windows 95 version:** preserved on branch `windows-95-classic` and tag `win95-final`
(commit 51a3789). It was removed from `main` in Oct 2026 at the user's request - don't bring
Windows-era names, copy or assets back into `main`.

Static assets in `public/`: `Shubham_resume.pdf`, `icon.svg` (app icon source), `favicon.ico`,
`favicon.png`, `apple-touch-icon.png`, `icon-192.png`, `icon-512.png`, `icon-maskable-192.png`,
`icon-maskable-512.png`, `og-image.jpg`, `sw.js`. `manifest.json`, `robots.txt` and `sitemap.xml`
are generated by `app/manifest.ts`, `app/robots.ts` and `app/sitemap.ts`.

## Design
- Apple-inspired, not Apple assets: no Apple logo (the menu-bar logo is our winking-monitor
  `BrandMark`), own app tiles (`AppIcon`: CSS gradient rounded square + white SVG glyph), own
  gradient wallpapers, no Apple fonts (no bundled SF). "Inspired by", never copied.
- Fonts (Oct 2026, user's pick): text uses the **device's own font** (`--font` system stack:
  Apple's font on Mac/iPhone, Segoe UI on Windows). Inter, Geist, Plus Jakarta Sans, Manrope and
  DM Sans were compared on the real page; the user preferred the system font. **JetBrains Mono**
  (SIL OFL, `next/font/google` in `app/layout.tsx`, downloaded at build and served from this site,
  `--font-mono`, used through `--mono`) is for the Terminal, dates, tech lines, skill tags and the
  visitor counter. Portfolio type scale: section titles 24px,
  body 15px / 1.6, tables and skills 14px, project/job titles 17px, stat numbers 28px. No italics
  (the user decided against them).
- Desktop vs phone is one media query: `(max-width: 700px), (max-height: 500px) and (pointer: coarse)`
  (`PHONE_QUERY` in `lib/motion.ts`, same query in `styles/ios.css`, which is imported last).
- Colors are CSS variables in `styles/base.css` with a light and a dark set (the dark set is
  duplicated under `prefers-color-scheme` for Auto). Accent `#0066cc` light, `#4da3ff` text +
  `#0068d6` fills dark, chosen for WCAG AA (Apple's `#007aff` fails for small text). Dark mode
  layers lighter as surfaces rise (page < card < rows); links/secondary buttons in the content are
  tinted accent so they read as clickable.
- One scrolling portfolio window, not a desktop simulator with a window per section (deliberate).
- Motion: Apple curve `cubic-bezier(0.32, 0.72, 0, 1)` + a gentle spring; everything is skipped
  under `prefers-reduced-motion`.

## Architecture
- `app/page.tsx` renders the portfolio sections (`components/portfolio/*`) as **Server Components**
  and passes them as props into the client desktop root `components/os/ShubhamOS.tsx`. All content
  is in the server HTML (SEO); the client only chooses which sections a tab shows and their order.
- Content lives in `data/*.ts` (profile, about, skills, projects, experience). Entries with
  `hidden: true` (BrowseAnywhere project, ShepHertz job) are kept but not rendered.
- `components/os/OsProvider.tsx`: one reducer for dialogs, menus, tab, toast and window status, plus
  stable actions (`useOsActions()`): `showToast`, `showMessage`, `openDialog`, `goToSection`,
  `openTerminal`, `openGame`, `openResumeWizard`, `toggleMenu`, `getDockIcon`, ... Components plug
  imperative handles/DOM nodes in via `connect.*` callback refs (`mainWindow`, `terminalWindow`,
  `mainDockIcon`, `terminalDockIcon`, `terminalConsole`, ...) because the React Compiler lint forbids
  passing ref objects around in render. Dialog ids: `message`, `closeConfirm`, `trash`, `game`,
  `settings`, `wizard`, `timeMachine`, `about`, `activity`. Window keys: `main`, `terminal`.
- `components/windows/Window.tsx` is the single generic window (drag, 8-edge resize, snap, zoom,
  minimize, phone Home button); reuse it for any new window. Discrete state is React state; live
  geometry and animations write styles via refs. It sets only `display: none` inline when hidden, so
  CSS picks grid (desktop) or flex (phones).
- `components/dialogs/Dialog.tsx` is the generic dialog: `kind: 'alert' | 'panel'`, focus in, Escape
  closes, focus returns. Panels are bottom sheets on phones (grabber, "Done"). Contents stay mounted
  while closed.
- CSS in `styles/*.css`, imported in order by `app/globals.css`. No Tailwind, no CSS-in-JS.
- localStorage-backed preferences use `lib/stored-value.ts` (`useSyncExternalStore`, server snapshot =
  default) so there are no hydration mismatches. Keys are in `lib/storage.ts`; their string values
  (`shubhamOsTheme`, ...) are kept as-is so visitors' saved settings carry over.
- Theme: Light / Dark / Auto via `data-theme` on `<html>`. **Default is Light** (the server HTML
  ships `data-theme="light"`); an inline pre-paint `<script>` in `app/layout.tsx` applies a saved
  choice (`next/script` `beforeInteractive` runs too late in the App Router). `<html>` has
  `suppressHydrationWarning`.
- Site URL for canonical/OG/sitemap: `lib/site.ts` -> `NEXT_PUBLIC_SITE_URL` ->
  `VERCEL_PROJECT_PRODUCTION_URL` -> `https://shubhamworks.vercel.app`.
- `public/sw.js` (cache `shubham-os-v4`; bump it when cached files change): network-first for pages,
  cache-first for `/_next/static`, stale-while-revalidate for other files. Production only.
- Vercel Web Analytics: `<Analytics />` in `app/layout.tsx`, rendered only when `process.env.VERCEL`
  is set (its script 404s off Vercel). Enabled once in the Vercel dashboard.
- Keyboard: Escape closes menus/dialogs; Enter/Space activates menu items, tabs and window buttons;
  Enter opens a focused desktop icon.
- `AGENTS.md` is auto-generated by `next dev`; leave it uncommitted.

## Desktop (computers)
- `MenuBar`: logo button `#logo-menu-button` opens `AppMenu` (`#logo-menu`), section links, clock.
- `Dock`: `#dock-portfolio`, `#dock-terminal`, `#dock-game`, `#dock-timemachine`, `#dock-activity`, `#dock-settings`, `#dock-resume`,
  `#dock-trash` (`#dock-more` is phone-only). Magnification is JS (`useMagnification`): cosine
  falloff by pointer distance against the resting layout, written to `--s` per item; items widen (so
  the dock grows) and icons scale from their bottom edge. Launch bounce animates the tile, not the
  button. Running dots.
- Portfolio window (`#window`) is laid out like a Mac app (CSS grid in `styles/window.css`): unified
  52px title bar, translucent sidebar (`.window::before`, backdrop blur) with the profile card (the
  server `InfoBar` with avatar initials; its "Name:/Role:/Status:" labels are visually hidden but kept
  for screen readers) and the section list (the tablist, colored `tab-tile`s, a selection highlight
  that glides between rows). Content and status bar on the right.
- Profile photo: `public/profile.jpg` (192px square crop of the user's photo; the original is kept
  in `assets/profile-photo.jpeg`, not served). Shown in the sidebar profile card (`InfoBar`, path in
  `PROFILE.photo`) and used as the JSON-LD `Person` image. Hidden in the phone info row.
- Window buttons (`.tl` in `styles/window.css`) follow macOS: 12px, 8px apart, each with a darker
  edge and a tinted symbol in its own color (shown while pointing at the group). The symbols are
  our own SVGs (`WindowGlyph` in `components/icons`), drawn on the button's 12x12 grid so they
  are centered and sharp; not Apple's artwork. They turn gray
  (`--tl-off`) while the browser window isn't focused (`data-inactive` on `<html>`, set in
  `useDesktopEvents`). Panels show the close button plus a gray, disabled minimize and zoom
  (exception: the green button works in the Time Machine and Activity Monitor, see below; its minimize stays gray on purpose -
  the genie can't copy the starfield canvas).
- Desktop icons (Shubham HD, Debug Runner, Time Machine, Activity Monitor, Terminal, Trash) in a top-right column; double-click with
  a mouse, single tap on touch. The default Aurora wallpaper drifts slowly (`LiveWallpaper`).
- Animations (`lib/motion.ts`, all return a cancel function):
  - Minimize = real genie: the window is copied into 10-16 horizontal strips (each only its slice's
    size; copies have no blur/shadow; off-screen sections become spacers) and each frame every strip
    gets a `matrix3d` "square to quad" transform onto its slice of a funnel into the dock icon.
    Transform-only, so nothing repaints per frame. It lagged badly when copies kept the sidebar blur
    and used clip-path - keep it transform-only.
    Exception: a window that is frosted glass itself (the Terminal) gets one funnel-shaped
    `.genie-glass` backing (its own blur + background, clip-path updated per frame) and its copies
    are drawn without a background. See-through strips showed dark lines where the 1px overlaps
    doubled up, light seams without the overlap, and lost the blur. The Terminal's invisible input
    is dropped from the copies (it's styled by id, which copies lose, and showed as a white box).
    The drop shadow stays on during the genie: the funnel is drawn with a canvas shadow (same blur
    radius as the window's computed `box-shadow`) into a quarter-size `<canvas class="genie-shadow">`
    that CSS stretches to full size. A CSS `filter: blur()` on a full-size element cost ~2x the
    slow frames on the user's integrated GPU (AMD Vega 3); scaling a filtered element with CSS
    doesn't reliably blur at the small size, the canvas does.
    Setup cost is mostly laying out the 10-16 copies. Each strip's copy swaps the blocks of the
    on-screen section that lie outside its slice for same-size empty boxes (`trimToSlice`; only
    blocks whose children's margins can't leak out: text-only blocks, tables, grids, flex). This
    was checked pixel-for-pixel against untrimmed copies on every tab. CSS `contain` on the strips
    made no measurable difference.
    Copies are prepared ahead of the click: when a mouse rests ~80ms on the window buttons or on
    the window's dock icon, `prepareGenie` (called from `Window.tsx`) builds the copies into an
    invisible layer (`.genie-layer--prepared`, opacity 0) so they are laid out and drawn before
    the click; a minimized window is displayed invisibly for a moment to be copied. On click,
    `genie` uses them only if still valid (same rect and scroll, no content mutations other than
    text, under 5s old), otherwise it builds anew as before. On the user's machine this cut the
    click-to-motion pause from ~58ms to ~9ms. The portfolio window's pause comes from its size
    and content (~10x the Terminal's elements), not from the shadow.
    Before copying, the genie fires `BEFORE_GENIE_COPY` on the window so JS-measured layout can
    re-measure (the sidebar's selection highlight is 0px wide while the window sits in the Dock).
  - Zoom = `animateFrame`: glides the real frame (inline !important left/top/width/height) while the
    tab panel is frozen at its final width, so text lays out once, not per frame.
  - `animatePopIn` uses WAAPI and never touches inline transform (the main window keeps inline
    `transform: none` once centered; `resetWindowStyles` preserves it).
  - Clicking the dock icon mid-minimize reverses it. `.os-animating` on `<html>` pauses the live
    wallpaper during window animations.

## Phones
- No fake status bar (Safari shows the real one). Windows are full-screen apps: the whole `.window`
  scrolls, title bar sticky, the tablist becomes a fixed bottom tab bar with `TabGlyph`s, the profile
  card becomes an info row, and a "< Home" button on the left of the title bar goes to the Home
  Screen. Closing an app zooms it into its Home Screen icon (WAAPI). (A fake iOS home indicator was
  tried and removed in Oct 2026: it sat on top of the iPhone's real one and nobody knew to tap it.)
- Tapping the title bar scrolls the app to the top, and so does tapping the current tab again. The
  iPhone's own tap-the-status-bar gesture can't work here: iOS only scrolls the page itself, and
  the app scrolls inside `.window`.
- `viewportFit: 'cover'` (in `app/layout.tsx`) makes `env(safe-area-inset-*)` real; `styles/ios.css`
  pads for the notch and the home bar (including sideways phones). `appleWebApp.title` names the
  Home Screen icon. The status bar is left at the default style: `black-translucent` would draw
  white clock text over the light title bar.
- The desktop layer is a Home Screen grid (the Terminal icon is hidden there, it's in the dock); the
  dock shows Shubham / Terminal / Settings / More (More opens `AppMenu` as an action sheet with a
  sticky Cancel). Alerts use stacked-button styling. Phones held sideways hide the info row.
- 16px inputs stop iOS zooming into fields.
- The portfolio's tables turn into stacked cards on phones; that rule is scoped to `.window` so
  other tables (Activity Monitor) stay tables.

## Features
- **Startup screen** (revamped Oct 2026): dark screen with a soft Aurora glow, the app icon springs
  in, then the user's name and role, a thin progress bar with plain steps ("Loading projects"...;
  "Welcome back" for returning visitors), then it zooms gently out into the desktop. Deterministic
  ~4.4s. Click or any key skips it ("Tap to skip" on touch screens). Timing is intentionally fixed;
  total must stay within 4-6 seconds if changed.
- **Terminal** (`components/windows/TerminalWindow.tsx`, commands in `lib/terminal.ts`): prompt
  `shubham@portfolio ~ %`, `help`, `whoami`, `skills`, `projects`, `resume`, `sudo hire-me`, history
  with Up/Down, zsh-style "command not found". Output persists across minimize/close; only `clear`
  empties it. The prompt line follows the output (one scrolling `.terminal-body`) and draws a block
  cursor (blinks when focused, hollow when not, follows arrow keys); the real `#terminal-input` is
  invisible and laid over the typed text, so typing, history and phone keyboards still work.
- **Debug Runner**: tiny jump-over-bugs game, best score in localStorage.
- **Time Machine** (`components/dialogs/TimeMachineDialog.tsx`, a wide panel dialog, always dark):
  the visible experience entries, oldest first, as "desktop snapshots" (own era gradient each)
  stacked in 3D perspective inside a deep-space backdrop. A canvas starfield (`lib/starfield.ts`,
  runs only while open) drifts and warps into streaks while traveling; a big year counter rolls
  through every year in between; newer snapshots fly past the camera. Travel by mouse wheel /
  trackpad (up = back in time, like macOS), sideways swipe on phones, arrow keys, the ‹ › buttons
  or the year rail (`role="tablist"`, roving focus). Reduced motion: no warp, no rolling.
  Green button (or double-clicking the title bar) glides it to full screen (`zoomed` /
  `onToggleZoom` on `Dialog`, desktop only); Escape leaves full screen first, then closes.
  Opens on the latest job. From the Dock, the desktop/Home Screen icon and the logo menu. Built
  only from `data/experience.ts` - no extra career content.
- **About This Developer** (`components/dialogs/AboutDeveloperDialog.tsx`): a Mac-style About
  window - photo, name, role and a playful spec list (Chip, Memory = years in IT, Storage = shipped
  projects, live Uptime since the career start, Serial number = GitHub), "More Info…" (About
  section) and "Resume…". Opened from the top of the logo menu, Shubham HD and the desktop's
  Get Info (it replaced the old one-line "About Shubham HD" joke message).
- **Activity Monitor** (`components/dialogs/ActivityMonitorDialog.tsx`, matching in
  `lib/skill-usage.ts`): the skills from `data/skills.ts` as processes (% CPU = the skill's level
  with a small live wobble, Kind = group, Level, made-up PID), filter by group, sortable columns,
  Up/Down to move, a scrolling load graph, and "Used in" listing the visible jobs and projects whose
  tags mention the skill (aliases like MUI/Material UI are matched). A "Threads = usage count"
  column was dropped: JavaScript/HTML/CSS aren't tagged anywhere and showed 0. Samples only tick
  while open; none under reduced motion. Green button = full screen. From the Dock, the
  desktop/Home Screen icon and the logo menu.
- **Sticky note** (`components/desktop/StickyNote.tsx`): yellow note in the top-left of the desktop
  (mouse-draggable), a 2x2 widget in the top-right of the phone Home Screen (icons fill the left half beside it,
  Trash continues below; the user's layout choice). Shows one of a few short mottos
  (written by Claude at the user's request), switching on the visitor's local hour (no
  "new note every hour" caption - the user removed it). Not in the
  server HTML (depends on the clock), via `useSyncExternalStore`.
- **System Settings** (`components/dialogs/SettingsDialog.tsx`): Light / Dark / Auto, 8 original
  gradient wallpapers (Aurora default, Lagoon, Dusk, Graphite, Sunrise, Bloom, Sky, Ember; unknown
  saved ids fall back to Aurora),
  Random Wallpaper, and a "Display & Text Size" section with **Larger Text** (`data-larger-text`
  on `<html>`; in `styles/effects.css` every UI text gets ~2px bigger font sizes only - no box,
  dialog, swatch or sidebar changes size (the user asked for no layout shift); phones have their
  own step up from `ios.css` sizes. The portfolio sections are the one exception: `zoom: 1.15`).
  It is saved like the theme and applied by the pre-paint script (`buildAppearanceInitScript`,
  `DISPLAY_FLAGS` in `lib/themes.ts`) so there is no flash. (CRT scanlines and mouse trails were
  removed in Oct 2026; a Reduce Transparency switch was tried and removed at the user's request.)
- **Right-click menu**: New Folder (joke), Get Info, System Settings..., Clean Up, Reload.
- **Trash** dialog (joke file list), quit alert on the main window's close button (Quit/Cancel just
  minimizes).
- **Resume installer** (`InstallWizardDialog`): one centered page per step ("Step N of 4"):
  welcome, license joke with a mandatory checkbox, a 1500ms deterministic progress bar, then Finish
  downloads the PDF. Opened from the Contact section, the logo menu, the Dock and the `resume` command.
- **Resume PDF**: generated with Python/reportlab from the same content as the page; a normal
  professional resume (deliberately not themed).
- **Contact form** (`components/portfolio/ContactForm.tsx`, `lib/contact.ts`): sends via
  **Web3Forms** (POST FormData to `https://api.web3forms.com/submit`) when `WEB3FORMS_ACCESS_KEY` is
  set (read on the server in `Contact.tsx` and passed to the client form; Web3Forms rejects
  server-side submissions on the free plan, so the browser submits and the key is public by design);
  otherwise, or if sending fails, it falls back to a prefilled `mailto:` link.
  - Hidden `botcheck` honeypot: ticked submissions are silently "accepted" and dropped.
  - Email + message are required; the form has `noValidate` and checks them itself (`validate()`),
    so errors show inline in the site style (red ring + `.field-error` linked via
    `aria-describedby`, first bad field focused) instead of the browser bubble.
  - Spam limits: `sendingRef` blocks burst submits in the same tick; each visitor may send 5
    messages per minute (send times in localStorage `shubhamOsContactSends` plus an in-memory copy;
    a "Please wait" toast keeps the typed text). hCaptcha (free on Web3Forms) only if spam shows up.
  - IMPORTANT (a bug fixed once): the toast must fire **before** the mailto navigation (wrapped in
    try/catch), because in some sandboxed/preview contexts that throws synchronously and kills the
    rest of the handler. Don't reorder this.
- **Project status badges**: green for Completed, orange for In Progress (`--orange` /
  `--orange-text` tokens, picked by `data-status`). "projects shipped" in the About window counts
  only Completed ones. The Terminal `projects` list is built from `VISIBLE_PROJECTS`.
- **Notifications**: generic `showToast(title, msg)`; reuse it for confirmations.
- **Visitor counter** chip in the status bar (`No. 004821`): locally seeded, not a real global
  count (its `title` says so).
- **App icon**: the winking monitor (one open eye, one winking arc, smile) on a blue app tile,
  drawn once in `public/icon.svg`. The PNGs/ICO are rendered from it with Playwright Chromium:
  rounded tile for `favicon.*` and `icon-192/512`; full-bleed square for `apple-touch-icon.png` and
  `icon-maskable-*` (iOS/Android mask them); `favicon.ico` holds 16/32/48 PNGs; `icon.svg` is also
  the SVG favicon. Many concepts were tried before the winking monitor; don't swap it for a generic icon.
- **Link previews**: Open Graph + Twitter tags from `lib/site.ts`. `og-image.jpg` (1200x630, JPEG
  ~105 KB to stay under WhatsApp's preview size limit) is a real screenshot of the desktop in a card
  that leads with "Portfolio / Shubham Chaudhary / Full Stack Engineer - 4+ years".
- **SEO**: meta description, JSON-LD `Person`, a visually hidden `<h1>`; section titles are `<h2>`
  inside each `<legend>` so headings go h1 -> h2 -> h3. `<main>` is the landmark; `role="tabpanel"`
  is on the div inside it.
- Lighthouse (local, light): accessibility 100 on desktop and phone. Performance on a throttled phone
  is limited mainly by hydrating the whole desktop; left as is.

## Known constraints
- Next.js App Router + TypeScript (strict) + hand-written CSS. Runtime dependencies are only
  `next`, `react`, `react-dom`, `@vercel/analytics` - don't add libraries without a clear reason.
  npm is the package manager.
- No backend - anything needing persistence beyond localStorage needs an explicit decision to add
  real infrastructure.
- Run locally with `npm run dev`; verify with `npm run build`, `npm run lint`, `npm run typecheck`,
  `npm run test:e2e`.
- **Browser tests**: Playwright (`@playwright/test`, dev-only, pinned 1.64.0 to match the Chromium
  build installed on the user's machine). `playwright.config.ts` builds into `.next-e2e` (via
  `NEXT_DIST_DIR`, read in `next.config.ts`) so the normal `.next` build is never replaced, with a
  fake `WEB3FORMS_ACCESS_KEY`; contact tests stub `api.web3forms.com` and the service worker is
  blocked. Never let tests send real mail (the user's Web3Forms quota is small). `tsconfig.json`
  lists `.next-e2e/types` by hand so `next build` doesn't rewrite it. Projects: `desktop` (all specs
  except mobile) and `phone` (375x667 touch, `mobile.spec.ts`). The lint config includes the React
  Compiler rules (`react-hooks/refs`, `immutability`, ...) - fix the design rather than disabling them.
