# Shubham Chaudhary — Portfolio Site (Windows 95 style)

## What this is
A single-page portfolio site styled as an interactive Windows 95/98 desktop.
**Migrated to Next.js (App Router, TypeScript strict) in session 6 (Oct 2026)** — see
"Architecture (Next.js)" below. The original single-file `index.html` was removed from the tree
after the migration was verified; it is preserved in git history (last at commit `2e3cc72`).
Static assets live in `public/`: `Shubham_resume.pdf`, `favicon.ico`, `favicon.png`,
`apple-touch-icon.png`, `og-image.png`, `icon-192.png`, `icon-512.png`, `wallpaper-*.svg`, `sw.js`.
`manifest.json`, `robots.txt` and `sitemap.xml` are now generated by `app/manifest.ts`,
`app/robots.ts` and `app/sitemap.ts`.

## macOS / iOS redesign — session 7 (Oct 2026, branch `feat/mac-ios-ui`)
At the user's request the Win95 look was replaced with an Apple-inspired one: **macOS on desktop,
iOS on phones** (`(max-width: 700px), (max-height: 500px) and (pointer: coarse)` — `PHONE_QUERY` in
`lib/motion.ts`, same query in `styles/ios.css`). Structure and portfolio content are unchanged;
only UI chrome labels were renamed. Where this section conflicts with older Win95 notes below
(design philosophy, palette, font, labels), this section wins.
- Not Apple assets: no Apple logo (menu-bar logo is our winking-monitor `BrandMark`), own app tiles
  (`AppIcon`: CSS gradient rounded square + white SVG glyph), own gradient wallpapers, system font
  stack only (no bundled SF fonts). Keep it "inspired by", like the Win95 version.
- Desktop: `MenuBar` (logo menu `#start-button` → `AppMenu` `#start-menu`, section links, clock),
  `Dock` (bounces Terminal/game on launch, running dots; Trash + Resume + game are mac-only),
  desktop icons in a top-right column. Old ids kept: `#taskbar-window-btn`/`#taskbar-dos-btn` are
  the Dock icons; actions renamed `toggleMenu`, `getDockIcon`, connectors `mainDockIcon`/`dosDockIcon`.
- Portfolio window = a modern Mac app (CSS grid in `styles/window.css`): unified 52px title bar,
  translucent sidebar (`.window::before`, backdrop blur) holding the profile card (the server
  `InfoBar`, with avatar initials; its "Name:/Role:/Status:" labels are visually hidden but kept for
  screen readers) and the section list (the tablist, colored `tab-tile`s, a selection highlight that
  glides between rows). Content + status bar on the right. Phones restyle the same markup back into
  the info row + bottom tab bar (`ios.css`). The Window component no longer sets inline
  `display: flex` (only `display: none` when hidden), so CSS chooses grid/flex.
- Dock magnification is JS (`useMagnification` in `Dock.tsx`): cosine falloff by pointer distance
  measured against the resting layout, written to `--s` per item; the item width grows (dock widens)
  and the icon scales from its bottom edge. Desktop pointer only.
- Motion (`lib/motion.ts`, all cancellable, return a cancel function):
  - Minimize on desktop = real genie: the window is copied into 10-16 horizontal strips (each only its
    slice's size, copies have no blur/shadow, off-screen sections replaced by spacers), and each frame
    every strip gets a `matrix3d` "square to quad" transform onto its slice of a funnel bending into the
    dock icon. Transform-only, so no repaint per frame. Was laggy before (24 blurred copies + clip-path
    repaints) - keep it transform-only.
  - Minimize on phones = iOS zoom into the Home Screen icon (WAAPI, corners round to the icon's).
  - Zoom (maximize/restore) = `animateFrame`: glides the real frame (inline !important left/top/width/
    height) while the tab panel is frozen at its final width, so text lays out once, not per frame.
  - Clicking the dock icon mid-minimize reverses it. `.os-animating` on <html> pauses the live wallpaper.
- Phones: no fake status bar (Safari shows the real one). Windows are full-screen apps (the whole
  `.window` scrolls; title bar sticky; tabs become a fixed iOS tab bar with `TabGlyph`s; a
  home indicator — tap or swipe up — minimizes). Desktop layer = Home Screen grid (Terminal icon
  hidden, it's in the dock); dock shows Shubham/Terminal/Settings/More (More opens `AppMenu` as an
  action sheet with a sticky Cancel). `Dialog` has `kind: 'alert' | 'panel'`; panels are bottom
  sheets on phones (grabber, "Done"), alerts get iOS stacked-button styling.
- Themes are now Light / Dark / Auto (`data-theme` on <html>; colors are CSS variables in
  `styles/base.css`, dark set duplicated under `prefers-color-scheme` for Auto). Same storage key
  `shubhamOsTheme`. **Default is Light** (user's choice; the server HTML ships `data-theme="light"`),
  default wallpaper Aurora. Dark palette layers lighter as surfaces rise (page < card < rows), and
  links/secondary buttons inside the content are tinted accent so they read as clickable. Accent `#0066cc` light, `#4da3ff` text +
  `#0068d6` fills dark — chosen for WCAG AA (Apple's `#007aff` fails for small text).
- Animations: Apple curve `cubic-bezier(0.32, 0.72, 0, 1)` + a spring. `animatePopIn` uses WAAPI
  and never touches inline transform (the main window keeps inline `transform: none` once centered;
  `resetWindowStyles` preserves it — clearing it re-applies the CSS centering and shifts the window).
- Renamed UI labels (content unchanged): Terminal (prompt `shubham@portfolio ~ %`), Trash, Shubham HD,
  System Settings, Install Shubham Resume (Continue/Go Back/Install), quit alert (Quit/Cancel),
  context menu New Folder/Get Info/Change Wallpaper…/Clean Up/Reload. Section headings lost their
  Windows file-name jokes (Skills.cfg → Skills, Projects\ → Projects, Experience\logs\ →
  Experience, Message.exe → Message, Stats.dat → Stats) and Send lost its brackets.
- Not yet updated (needs the user's decision): `public/og-image.png` (a Win95 window mockup) and the
  SEO/social copy in `lib/site.ts` ("Boots Like Windows 95"); README already describes the new look.
- The bouncing "SHUBHAM OS" DVD logo was removed (didn't suit the Apple look); the default Aurora
  wallpaper now drifts slowly instead (`LiveWallpaper`, CSS transforms, off under reduced motion).
- The resume installer is a single centered page per step ("Step N of 4"), no step sidebar.
- Lighthouse (local, light): accessibility 100 on desktop and phone.

## Architecture (Next.js) — session 6
- `app/page.tsx` renders the portfolio sections (`components/portfolio/*`) as **Server Components**
  and passes them as props into the client desktop root `components/os/ShubhamOS.tsx`. All content
  is in the server HTML (SEO); the client only chooses which sections a tab shows and their order.
- Content lives in `data/*.ts` (profile, about, skills, projects, experience). Entries that were
  commented out in the old HTML (BrowseAnywhere project, ShepHertz job) are kept with `hidden: true`.
- `components/os/OsProvider.tsx`: one reducer for dialogs, menus, tab, toast and window status, plus
  stable actions (`useOsActions()`): `showToast`, `showMessage`, `openDialog`, `goToSection`,
  `openDos`, `openGame`, `openResumeWizard`, ... Components plug imperative handles/DOM nodes in via
  `connect.*` callback refs (the React Compiler lint forbids passing ref objects around in render).
- `components/windows/Window.tsx` is the single generic window (replaces `makeDraggable()` /
  `makeResizable()`); reuse it for any future sub-window. Discrete state (visible, maximized/snapped,
  dragging) is React state; live drag/resize geometry and animations write styles via refs.
- `components/dialogs/Dialog.tsx` is the generic dialog (open/close animation, focus in, Escape closes,
  focus returns). Dialog contents stay mounted while closed, like the original.
- CSS: the original stylesheet split verbatim into `styles/*.css` (class names unchanged), imported in
  order by `app/globals.css`. No Tailwind, no CSS-in-JS.
- localStorage-backed preferences use `lib/stored-value.ts` (`useSyncExternalStore`, server snapshot =
  default) so there are no hydration mismatches. Keys are unchanged from the original.
- The pre-paint theme script is an inline `<script>` in `app/layout.tsx` `<head>` (`next/script`
  `beforeInteractive` runs too late in the App Router). `<html>` has `suppressHydrationWarning`.
- Site URL for canonical/OG/sitemap: `lib/site.ts` → `NEXT_PUBLIC_SITE_URL` →
  `VERCEL_PROJECT_PRODUCTION_URL` → `https://shubhamworks.vercel.app`.
- `public/sw.js` (cache `shubham-os-v2`): network-first for pages, cache-first for `/_next/static`,
  stale-while-revalidate for other files. Registered in production only. (The old SW pre-cached a
  non-existent `./resume.pdf`, so it never installed.)
- Small, deliberate behavior additions: Escape closes menus/dialogs; Enter/Space activates menu items,
  tabs and title-bar buttons; Enter opens a focused desktop icon.
- `AGENTS.md` is auto-generated by `next dev` (Next 16.4); harmless.
- **Vercel Web Analytics** (Oct 2026): `@vercel/analytics` `<Analytics />` in `app/layout.tsx`, rendered
  only when `process.env.VERCEL` is set (its `/_vercel/insights/script.js` 404s off Vercel). Must be
  enabled once in the Vercel dashboard (project → Analytics → Enable).

## Design philosophy (do not violate without asking)
- **Very minimal CSS, intentionally simple.** The Win95 bevel/border look (outset/inset borders)
  IS the design — don't add gradients, shadows, or modern flourishes beyond what's already there.
- **Single scrolling window**, not a multi-window "desktop simulator." We deliberately chose this
  over draggable-windows-for-every-section early on, for simplicity.
- Palette: gray `#c0c0c0`, navy `#000080`, classic Win95 3D bevel borders throughout.
- Font: "MS Sans Serif", Tahoma fallback.
- Custom icons are hand-drawn inline SVG in the Win95/98 visual language — not emoji, not real
  Microsoft assets (avoid copyright issues, keep it "inspired by" not "copied from").

## Structure of the page
Header → About → Skills → Projects → Experience → Contact → Footer, all inside one
draggable/resizable/minimizable/maximizable "window" (`#window`), sitting on a "desktop layer"
with icons, a DVD-bounce easter egg, a taskbar, and a Start menu.

## Features currently implemented
- **Boot screen**: BIOS-style boot sequence on load, deterministic ~5.3s total (lines type in,
  a "verifying disk integrity" beat, a progress bar with fixed animation duration). Click or any
  keypress skips it. Timing is intentionally fixed (not randomized) — total time must stay
  strictly within 4–6 seconds if changed.
- **Main window**: draggable (by title bar), resizable (8 edge/corner handles with native
  ns/ew/nwse/nesw resize cursors), minimizable (hides + reveals desktop layer behind it),
  maximizable, and snappable (drag to screen edges to snap left/right, drag to top to maximize —
  like Windows Aero snap).
- **DOS Prompt** (`#dos-window`): a separate floating sub-window, ALSO draggable/resizable/
  minimizable/maximizable (uses the same generic `makeDraggable()`/`makeResizable()` helper
  functions as the main window — reuse these for any future sub-windows rather than duplicating
  drag/resize logic). Has a real command parser (`whoami`, `skills`, `resume`, `sudo hire-me`,
  etc. — see `DOS_COMMANDS` object). Output persists across minimize/maximize/close since the
  DOM node is only hidden, never cleared (only the `clear` command clears it).
- **Debug Runner**: a tiny jump-over-bugs game (desktop icon + Start menu), best score saved in
  `localStorage`.
- **Desktop icons**: Recycle Bin, My Computer, Debug Runner, MS-DOS Prompt — all draggable
  around the desktop layer independently of the window.
- **DVD bounce easter egg** (REMOVED in session 7, replaced by the drifting Aurora wallpaper):
  "SHUBHAM OS" text bounced around the desktop layer **all the time**,
  behind every window (changed Oct 2026 at the user's request; it originally bounced only while the
  main window was minimized and froze in place otherwise). Still under `prefers-reduced-motion`. It used to trigger a joke error dialog every 14th bounce (reduced from
  every 4th because it felt spammy); those dialogs were later **removed entirely** in commit
  `f6ed8d3` ("remove random dialog boxes"). Only the bounce remains — don't re-add the dialogs
  without being asked.
- **Right-click context menu**: custom menu (Refresh, Arrange Icons, Display Properties,
  Properties, New Text Document joke).
- **Display Properties / wallpaper picker**: 9 wallpapers total, persisted via `localStorage`
  under `shubhamOsWallpaper`. Four solid/pattern entries: Teal (default), Navy, Maroon, Stripes.
  Five scenic SVG entries: Sunset Hills, City Dusk, Countryside, Beach, Space (files:
  `wallpaper-sunset-hills.svg`, `wallpaper-city-dusk.svg`, `wallpaper-countryside.svg`,
  `wallpaper-beach.svg`, `wallpaper-space.svg`). SVG entries use `type: file` pattern in the
  WALLPAPERS array — `applyWallpaperOnly` sets `background-image: url(file)`, `background-size:
  cover`, `background-position: center` for these. No real Microsoft wallpapers (copyright).
- **Contact form** (`components/portfolio/ContactForm.tsx`, `lib/contact.ts`): sends via
  **Web3Forms** (POST FormData to `https://api.web3forms.com/submit`) when
  `WEB3FORMS_ACCESS_KEY` is set (Oct 2026; read on the server in `Contact.tsx` and passed to the
  client form as a prop — Web3Forms rejects server-side/proxied submissions on the free plan, so the
  browser must submit and the key is public by design); otherwise, or if sending fails, falls back to
  a prefilled `mailto:` link. Hidden `botcheck` checkbox honeypot (submissions with it ticked are
  silently "accepted" and dropped). Email + message are `required`; the form has `noValidate` and checks them itself (`validate()` in `ContactForm.tsx`) so errors show inline in the site style (red ring + `.field-error` message linked via `aria-describedby`, first bad field focused) instead of the browser's bubble. Spam limits (Oct 2026): a ref
  (`sendingRef`) blocks burst submits fired in the same tick, and each visitor may send up to 5 messages
  per minute via Web3Forms (send times as a JSON array in `shubhamOsContactSends` in localStorage, plus an in-memory copy; a "Please wait"
  toast keeps the typed text). hCaptcha (free on Web3Forms) is the next step only if spam shows up. The Email button in the links
  row stays as a mailto fallback. IMPORTANT bug we already fixed once: the toast confirmation must
  fire **before** attempting the mailto navigation (wrapped in try/catch), because in some
  sandboxed/preview contexts that throws synchronously and kills the rest of the handler. Don't
  reorder this.
- **Toast notifications**: generic `showToast(title, msg)` — reused for form submission
  confirmation. Feel free to reuse this for other confirmations rather than building new UI.
- **Resume download**: `resume.pdf` was generated with a Python/reportlab script from the same
  content as the page (see "Content source" below) — it's a normal clean resume, NOT styled like
  Win95 (deliberate — a resume should look professional).
- **Favicon**: a hand-drawn "winking CRT monitor" icon (blue screen, one open eye, one winking
  arc, smile). We went through several concepts (Tetris S-piece, Debug Runner bug mascot,
  terminal prompt, floppy disk, winking CRT) before landing on this one. Don't revert to a
  generic Windows-flag-style icon.
- **Link previews**: Open Graph + Twitter Card meta tags in `<head>`, `og-image.png` is a mockup

## Window animation system (session 5)
All window/dialog animations are managed entirely via inline JS `style.transition` — no CSS
transition declarations on `.window` or `.subwindow` (the old `transition: transform 0.3s ease`
on `.window` was removed). The `.window.minimized` CSS rule was removed entirely; hidden state
is tracked via the JS property `winEl._isMinimized`.

Shared helpers (both #window and #dos-window reuse them):
- `animateWindowToTaskbar(winEl, btnEl, onDone)` — shrinks winEl into btnEl via
  `translate + scale` transform over 200ms ease-in. Computes scale/offset from live
  `getBoundingClientRect()` on both elements. Sets `pointerEvents: none` during flight.
  Calls `onDone()` at 215ms (which should `display:none` and reset styles).
- `animateWindowFromTaskbar(winEl, btnEl, onDone)` — reverse: winEl must already be
  `display:flex, transform:none` before calling. Sets the FROM transform (button position),
  forces reflow, then transitions to `transform:none` over 200ms ease-out.

Other animations:
- **Open (main window)**: `scale(0.94)→scale(1)` + opacity 0→1 over 170ms on first `initApp()`.
- **Open (DOS, fresh)**: `scale(0.9)` + opacity 0→1 over 150ms when opened from hidden state.
- **Maximize/restore toggle** (both windows): quick opacity 0.75→1 crossfade (~80ms+150ms)
  bracketing the class change — avoids layout transition issues with `!important` overrides.
- **DOS close** (✕ button): `scale(0.94)` + opacity fade over 120ms before `display:none`.
- **Dialogs**: `openDialog` → `.dialog-box` scale 0.92→1 + opacity over 130ms. `closeDialog`
  → 0.92 + opacity over 100ms, then `display:none`. Overlay's `_closeTid` prevents open/close
  race conditions.

Guards:
- `winEl._animating` flag prevents stacking/interrupting animations. `toggleTaskbarWindow`
  and `toggleDosWindow` are no-ops while `_animating` is true.
- `restoreWindow` / `restoreDos` cancel in-progress minimize via `clearTimeout(win._animTid)`
  and reset styles before starting the reverse animation.
- `const reducedMotion = window.matchMedia('(prefers-reduced-motion: reduce)').matches` — all
  animations skip entirely (instant show/hide) when this is true.
- Drag/resize handles are unaffected: `makeDraggable` sets `transform: none` on mousedown which
  cancels any in-flight animation, but only during live drag (acceptable). The 8-edge
  `makeResizable` handlers have no interaction with the animation system.

## Features added (session 4)
Six interactive/visual features, all opt-in or localStorage-backed. New localStorage keys:
- `shubhamOsTheme` — theme id ('win95' / 'win98' / 'terminal'). Early-applied in a `<head>` inline
  script to avoid flash of default state. Exposed via Display Properties as 3 swatch buttons.
- `shubhamOsCrt` — '1' if CRT scanlines+vignette overlay is enabled. Toggle in Display Properties.
  Overlay is a fixed `#crt-overlay` div with `pointer-events:none`, z-index 999.
- `shubhamOsCursorTrail` — '1' if mouse trail is enabled. 10 pooled DOM dots recycled on mousemove,
  throttled to ~25 fps, fade via CSS opacity transition.
- `shubhamOsVisitCount` — incrementing integer, incremented on DOMContentLoaded (before runBoot).
  On visit ≥ 2, replaces bootLines[1] with "Welcome back. Session #N." (no timing change).
- `shubhamOsVisitorNum` — seeded counter starting 3100–4900, incremented +1–7 on each visit.
  Displayed in the footer status bar as a retro green LCD chip (`No. 004821`). NOT a real global
  count — displayed with a `title` attribute noting it's locally seeded.
- Startup chime: was built (Web Audio API, G4+C5 tones), then removed — browser autoplay policy
  makes it unreliable for first-time visitors with no interaction. No audio logic remains.
- Display Properties dialog extended: now has Theme (top), Background (middle), CRT+Trail toggles
  (bottom). Dialog body has `id="theme-swatches"` rebuilt on open.
- Terminal theme uses `[data-theme="terminal"]` attribute on `<body>` for a single CSS override
  (`.exp-duration` color fix). Theme application also sets `data-theme` on `document.documentElement`
  from the early `<head>` script.
